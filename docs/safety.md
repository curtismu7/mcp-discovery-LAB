# Safety

This app inspects tool metadata that servers supply, and that metadata is untrusted. It is built so that running it, in its default mode, cannot reach anything real. Each rule below names the test that enforces it. Run them all with `npm test`.

| Rule | Enforced by |
| --- | --- |
| Demo mode is the default. It scans fixtures and in-process stub servers only; the real host is never read. Live mode needs `MCP_DISCOVERY_LIVE=1` exactly (`true`, `yes`, `0` and the empty string are refused by the doctor, not treated as on). | `server/test/safety.test.js`: "live mode needs exactly MCP_DISCOVERY_LIVE=1" and "default mode: a full scan makes zero non-loopback connections, only ever touches stub ports, and never reads the real host" (every child-process and file-read function is replaced by one that records and throws, for the whole scan). |
| Only `server/src/live.js` starts a process (`ps`, `lsof`, `docker ps`, fixed argv, no shell), and only `runtime.js` can import it, and only in live mode. | `safety.test.js`: "source scan: only live.js starts processes or reads files for the host". |
| Default mode makes no non-loopback connection of any kind: no socket, no DNS lookup, no `fetch`. | `safety.test.js` (the guard in `server/test/netguard.js` blocks and records them; also run through `POST /api/scan`), "the guard itself works". |
| A probe contacts a loopback host only, and in demo mode only the stub ports. A remote URL is listed and never contacted. | `server/test/policy.test.js` ("the loopback scope allows only loopback hosts"), `scanner.test.js` ("stdio and remote candidates are never contacted"), `probe.test.js`. |
| A listener is probed only when something says it is an MCP server (a Compose service, a client-config entry, or a pid that is an MCP-looking process). A random local service is never sent a request. | `scanner.test.js`: the `postgres 5319` decoy is `probe_skipped_unconfirmed` with no attempt. |
| A probe sends `server/discover`, `initialize`, `notifications/initialized` and `tools/list` and nothing else. No tool is ever invoked. | `scanner.test.js`: "only the listed tool methods are sent". |
| No credential is accepted or sent. A request with `Authorization`, `Proxy-Authorization` or `X-API-Key` is refused (400). `POST /api/scan` and `POST /api/reset` take no body fields. A server that answers 401/403 is reported as `auth_required` and is not retried with anything. | `server/test/api.test.js`: "credentials are refused"; `scanner.test.js`: the auth stub records that no credential header ever arrived. |
| CSRF: a state-changing request (anything but GET/HEAD/OPTIONS) is refused with 403 when `Sec-Fetch-Site` is `cross-site` or when `Origin` is present and is not an `http` loopback origin identical to the `Host` it was sent to (`null` is refused); a request with a body must be `application/json` (415). A page on another site can therefore not call `/api/scan` or `/api/reset`. Same-origin pages, the Vite dev proxy (forwards Host and Origin unchanged), `curl` and `scripts/e2e.mjs` still work. | `api.test.js`: "CSRF: a cross-origin or cross-site POST is refused", "a request body must be application/json". |
| Scans are serialised, and at most one waits (a third gets 429). | `scanner.test.js`: "scans are serialised", "the scan queue is capped"; `api.test.js`: "a third concurrent scan gets 429". |
| The server binds `127.0.0.1` only, refuses another address unless `MCP_DISCOVERY_BIND` is set, and refuses any non-loopback bind together with live mode. A missing, malformed (`127.999.999.999`, `[::1]junk`) or non-loopback `Host` header gets 421, for the API and the static UI alike. | `safety.test.js`: "binds loopback by default", "a started server is actually listening on loopback only"; `api.test.js`: "a non-loopback Host header is refused", "a missing Host header (HTTP/1.0) and malformed loopback Hosts are refused", "the built UI is served by the server itself". |
| The server serves the built UI (`web/dist`) itself with `default-src 'self'; script-src 'self'; connect-src 'self'` and no remote origin; `/api` keeps `default-src 'none'`. A 500 never returns `err.message` or a stack, a bad URL encoding is a 400. | `api.test.js`: "the built UI is served by the server itself", "a 500 never leaks", "GET /api/inventory/%ZZ is a 400". |
| A probe never follows a redirect (`redirect: 'manual'`); the loopback policy check and the `allowedPorts` check each reject on their own (live mode has no `allowedPorts`, so the policy check is the only gate there); the live command allow-list is exactly `ps`, `lsof`, `docker`; private ranges (10/8, 172.16/12, 192.168/16, 169.254/16, `::ffff:`, `fc`/`fd`/`fe80`) are refused for remote targets. | `probe.test.js` ("a redirect is never followed", "the loopback policy check rejects ... with no allowedPorts", "the allowedPorts check rejects ..."), `live.test.js`, `policy.test.js` ("private ranges"). |
| The credential guard runs before `/api/health`; `POST /api/reset` takes no body. | `api.test.js`: "the credential guard runs before /api/health", "POST /api/reset with a body is refused". |
| Every port is in 5300-5999. | `safety.test.js` and the doctor's `port-range` check; `scripts/compose.test.mjs` for the published port. |
| Secret-looking strings (secret query parameters and URL-fragment pairs such as `#access_token=`, URL userinfo, `--api-key=...`, `my_token=...` in any case, `password: x`, `x-api-key: x`, `Cookie:` / `Set-Cookie:` / `Authorization:` values, bearer tokens, JWTs, AWS access key ids, PEM blocks, token-shaped strings) are redacted before a record is stored or returned; any field whose name looks secret (`token`, `secret`, `password`, `api key`, `cookie`, `authorization`, `credential`, `signature`) is replaced by `[REDACTED]` at any depth of `serverInfo`, `capabilities` and the record; `headers`, `env` and `environment` fields are dropped at any depth, in any letter case. Tool names (`toolHashes` keys) and `inputSchema` property names are data and are not treated as field names. The probed URL is redacted before it is contacted. | `policy.test.js` ("redaction" tests), `scanner.test.js`: "secret-looking strings in the fixtures never reach the scan output", "secret query parameters are removed from the URL before it is probed". |
| Server-provided strings (names, descriptions, schemas, instructions) are untrusted data: hidden and control characters (zero-width, bidi, tag characters, U+2028/2029, musical formatting characters, lone surrogates and the rest of `INVISIBLE`) are shown as `[U+XXXX]`, sizes and depth are bounded, they are served only as JSON with `nosniff` and `Content-Security-Policy: default-src 'none'`, and nothing is evaluated or followed. | `sanitize.test.js`, `scanner.test.js`: "server-provided text is inert in records", `api.test.js`: "responses are JSON with nosniff". |
| The container publishes its port on loopback only (the server binds `0.0.0.0` inside it, which `MCP_DISCOVERY_BIND` opts in to; the Host and Origin guards still apply to the published port), with no host mounts, no docker socket, no host network and no `MCP_DISCOVERY_LIVE`; the image builds and serves the UI. | `scripts/compose.test.mjs`. |
| No real credentials in the repo. | `.githooks/pre-commit` runs gitleaks on staged changes when it is installed. The only secret-shaped strings are the obviously fake ones in `server/src/demo/fixtures.js`. |

## Live mode

`MCP_DISCOVERY_LIVE=1 npm start` reads this machine: `ps`, `lsof` (listening TCP), `docker ps`, and the client config files named in `MCP_DISCOVERY_CONFIG_PATHS`. It is read-only, loopback and stdio only, and the output is redacted the same way. It is not covered by the automated tests against a real host (they use the same parsers on fixtures); see the README for what was and was not run.

What live mode still does: it sends the four JSON-RPC methods above, as POST requests, to loopback ports it has reason to think are MCP servers. A POST is not guaranteed to be free of side effects on a server that is not what it says it is. That is why unconfirmed listeners are skipped.

## What is not covered

- **Cookie headers are not checked and never read.** Cookies are scoped by host, not port, so other local apps' cookies reach this server; it does not look at them, does not refuse them, and does not send any.
- Stdio servers are listed from the process table and client configs and are never started or attached to, so their tools are not inspected.
- Remote servers are not probed at all in this version.
- **The metadata hash covers only `name`, `description` and `inputSchema` of each tool** (object key order and tool order are ignored). A change to anything else is not noticed: a tool's `title`, `annotations`, `outputSchema`, `icons`, `_meta` or any other tool field, and at server level `serverInfo`, `protocolVersion`, `capabilities` and `instructions`. A server can change those between scans without a rug-pull flag. (The rug-pull baseline is the last scan that got an answer: a timeout or a 401 in between does not reset it.)
- The metadata checker is small on purpose. It looks at the tool name, description, and in `inputSchema` the property names and every `description`, `title`, `$comment`, `default`, `const`, `example`, `examples` and `enum` string, for hidden characters and a handful of English instruction patterns, after NFKC folding and a small Cyrillic/Greek lookalike table; and it flags broad schemas (also nested `additionalProperties: true`) and schemas deeper than 32 levels or larger than 5000 nodes (`too-deep`, fail closed). A clean result means none of that matched, not that a server is safe. Still **not detected**: instructions in another language or paraphrased; encoded or split text (base64, rot13, one phrase spread over several fields); lookalike letters outside the built-in table; strings in other schema keywords (`pattern`, `format`, `$id`, `required` entries, `$ref` targets, `patternProperties` names); `outputSchema`, `annotations`, `title` and `_meta` of the tool; text in `serverInfo` and `instructions` (those are made inert and shown, not checked); links or markdown images used to leak data; a tool whose behaviour differs from its description.
- Redaction is pattern based. A secret in a shape none of the patterns knows, in a field with an innocent name, is not removed.
- A concurrent POST to `/api/scan` beyond the one running and one queued is refused (429); there is no other rate limit.
